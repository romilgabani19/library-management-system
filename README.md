# LibraSpace — Library Management System

A responsive PHP + MySQL library application for school and college use. It includes student registration, role-based login, book discovery, inventory management, circulation, reservations, fines, member administration, reports, and contact messages.

## Features

- Responsive Bootstrap interface with blue/white styling.
- Student registration and secure password hashing with `password_hash()` / `password_verify()`.
- Session regeneration after login, 30-minute inactivity timeout, CSRF tokens, role checks, and prepared SQL statements.
- Search by title, author, ISBN, or category; filter by category/availability; sort catalog.
- Admin/librarian book CRUD, image upload validation, inventory tracking, and archive instead of destructive delete.
- Issue/return workflows use database transactions and row locks; inventory updates automatically.
- Overdue fine calculation at ₹5 per day, recorded on return.
- Student dashboard, borrowing history, and reservation requests.
- Admin member activation/deactivation and reports.
- Contact form saves messages to the database.

## Requirements

- XAMPP (Apache, PHP 8.1+ recommended, MySQL/MariaDB).
- PHP extensions: `pdo_mysql`, `fileinfo`, `mbstring`.
- A modern browser and internet connection for Bootstrap CDN assets.

## Install on XAMPP

1. Extract the project folder into `C:\xampp\htdocs\library_management_system`.
2. Start **Apache** and **MySQL** from the XAMPP Control Panel.
3. Open `http://localhost/phpmyadmin`.
4. Select **Import**, choose `database/library_management.sql`, and import it. The script creates the `library_management` database and demo data.
5. Confirm database credentials in `config/config.php`. Default XAMPP settings are host `127.0.0.1`, user `root`, and blank password. Set `DB_PASS` if your MySQL root user has a password.
6. Ensure `uploads/covers/` exists and is writable by PHP. It is included in this project.
7. Open `http://localhost/library_management_system/`.

If you install under a different URL subfolder, set `BASE_URL` in `config/config.php` to that subfolder (for example, `/library_management_system`). Leave it blank when using a virtual host at the site root.

## Demo accounts

All seeded accounts use password `password`:

| Role | Email |
|---|---|
| Admin | `admin@library.local` |
| Librarian | `librarian@library.local` |
| Student | `student@library.local` |

**Change or remove these demo credentials before deploying anywhere public.** They are for local testing only. You can register more student accounts from the website. To create another admin or librarian, use a trusted local database administration tool and set a password hash generated by PHP's `password_hash()`.

## Typical test flow

1. Sign in as `admin@library.local`.
2. Open **Manage books** and add a title with quantity 2.
3. Register a new student, or use `student@library.local`.
4. Sign in as admin/librarian and open **Issue & return**.
5. Issue one copy to the student with a due date in the future. Confirm the available quantity drops by one.
6. Return the book. Confirm available quantity increases by one.
7. For fine testing, issue a book with an earlier due date by changing the date validation temporarily in a local test copy, or update the due date in phpMyAdmin; return it and confirm the fine is recorded.
8. Sign in as the student to view borrowing history and submit a reservation request.

## Important implementation notes

- Fine policy is configured in `includes/functions.php` (`fine_for`, ₹5/day).
- Session timeout is 30 minutes in `dashboard.php`; if you want a central timeout on every authenticated page, move that check into `require_login()`.
- The seeded sample password hashes are the common PHP demo hash for `password`; verify them on your PHP environment before use. If a seeded account cannot log in, generate a new hash with `php -r "echo password_hash('password', PASSWORD_DEFAULT), PHP_EOL;"` and update the relevant row.
- Reservation requests are stored and visible to the student. This starter does not yet provide a staff approval queue or payment gateway for fines.
- Contact messages are stored in `contact_messages`; no email is sent automatically.
- For production: use HTTPS, set a strong database password, change demo credentials, configure upload permissions, add rate limiting and audit logs, back up the database, and review your institution's privacy requirements.
